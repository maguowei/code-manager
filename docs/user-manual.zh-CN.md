## 核心概念

### 配置

配置是最终可以应用到 `~/.claude/settings.json` 的用户配置集，包含认证密钥、API 连接地址、默认模型、权限控制、Sandbox、Hooks、插件列表以及状态行等完整选项。

- **供应商联动**：配置可以引用一个内置供应商。应用配置时，Code Manager 会将供应商的预置环境变量（服务地址与模型映射）与配置自身的选项合并，生成标准 JSON 并安全写入 `~/.claude/settings.json`。
- **自动接管**：如果本机已存在现有的 `~/.claude/settings.json`，在尚未创建任何配置时，配置页会自动识别并支持一键导入为受管配置。
- **外部变更感知**：当激活的配置被外部编辑器修改导致内容不一致时，配置页会弹出差异提示，你可以对比 Diff 后选择「接受实际配置」写回托管记录，或选择「重新应用」覆盖外部改动。

### Provider（供应商）

供应商承载客观的服务端点信息（API 连接地址、官方模型映射及附加环境变量），不包含任何私有认证密钥，且全部为内置只读，不支持自定义新增。

- **覆盖规则**：配置引用供应商后，配置中定义的同名字段会覆盖供应商的预置环境变量（连接地址除外：连接地址以供应商预置为单一事实源）。
- 完整内置供应商清单参见 [供应商 Provider](#供应商-provider) 章节。

### 记忆

记忆对应 Claude Code 的用户级系统指令文件 `~/.claude/CLAUDE.md` 与规则目录 `~/.claude/rules/*.md`，启用后才会同步写入到真实磁盘目录。

- **`CLAUDE.md`**：主记忆文件，全局同一时间只能启用一份，适合作为长期稳定的主指令基线。
- **Rules 规则**：模块化规则文件，可同时启用多份，保存在 `~/.claude/rules/` 下，支持在文件头配置 `paths` glob 进行路径匹配过滤。

### Skills

Skills 对应 Claude Code 的自定义技能扩展，位于 `~/.claude/skills/<id>/SKILL.md`。

- **启停机制**：启用的 Skill 保存在 `~/.claude/skills/`；禁用的 Skill 会安全移至 Code Manager 应用数据目录下的 `skills-disabled/` 归档。
- **软链接管理**：支持导入软链接形式的 Skill，可以正常启停切换，但由于源目录位于外部，其正文内容为只读，需在源目录中进行编辑。

### Stats 与 Usage 的区别

两者的数据源与统计口径截然不同：

- **使用统计（Stats）**：直接读取 `~/.claude.json` 中的本地统计快照，呈现累计启动次数、工具调用频次、Skill 使用量以及各项目最近一次会话概要。
- **Token 用量（Usage）**：增量扫描 `~/.claude/projects/**/*.jsonl` 与 `subagents/*.jsonl` 会话日志，基于 SQLite 缓存按日期、项目、会话与模型多维度聚合 Token 用量与成本支出。

> [!TIP]
> 排查费用消耗或准确 Token 统计时，请优先参考「Token 用量」页面。

## 快速开始

1. **获取安装包**：从 GitHub Release 页面下载当前平台的安装包，安装并启动。
2. **首次启动检测**：启动后，应用会自动读取本机现存的 `~/.claude`、`~/.claude.json` 和 `~/.claude/projects/`。
3. **macOS 隔离放行（可选）**：若首次打开遇到 Gatekeeper 拦截，可在终端执行 `xattr -rd com.apple.quarantine /Applications/code-manager.app` 移除隔离属性。

推荐的首次配置流：

1. **基础环境偏好**：打开左下角「设置」，选择界面语言、主题风格、默认终端与编辑器。
2. **创建 Profile**：进入「配置」页新建配置，在「供应商」选项中选择匹配的内置服务商。
3. **填入 API 凭据**：填入对应的 API 密钥并确认模型参数。
4. **测试连通性**：点击「测试模型」，验证连接地址、Token 密钥与模型是否通信正常。
5. **一键生效应用**：点击「启用」，将当前配置安全写入 `~/.claude/settings.json`。
6. **目录总览核验**：进入「`~/.claude` 目录总览」，确认文件生成与内容符合预期。

## `~/.claude` 目录总览

点击左上角的 `AI` 入口即可打开目录总览：

- **文件浏览与预览**：在右侧目录树选择文件后，左侧工作区将打开对应预览标签页。Markdown 文件默认展示排版渲染（支持切换查看源码），代码文本展示高亮源码，二进制文件展示格式与元数据。预览底部常驻文件大小、修改时间、字符编码与截断状态。
- **快捷工具与文件操作**：工具栏支持一键复制绝对路径、在系统文件浏览器中定位、调用默认编辑器打开。在目录树中右键可新建文件、新建文件夹、重命名或删除。
  > [!WARNING]
  > 目录删除操作不可逆。在操作 `settings.json`、`CLAUDE.md`、`rules/` 或 `skills/` 时，请务必提前确认已有安全备份。
- **软链接保护机制**：目录总览完整列出 `~/.claude` 下的文件与软链接。软链接带有明显标签且支持只读查看；为防止误改外部目录，任何经过软链接的路径均禁用新建、重命名与删除操作。扫描自动忽略 `node_modules`，并在超出深度或条目上限时给出提示。

## 配置

配置页是统一管理 Claude Code 配置项的核心控制台。

### 配置列表

卡片集中呈现每个 Profile 的核心状态：名称、描述、生效状态、主力模型、思考程度（Effort）、权限模式、Sandbox 状态、已启用插件摘要以及最近一次连通性测试结果。

- **丰富操作**：支持新建、启用（写入 `~/.claude/settings.json`）、复制环境变量文本（生成标准的 `export KEY="value"` 格式）、导出配置（可选是否携带认证密钥，并在落盘前预览最终 JSON）、克隆副本、编辑、删除以及拖拽排序。
- **一键测试全量配置**：支持对所有托管配置执行批量连通性检测。
- **团队基线同步**：在已启用的配置上，支持一键「同步常用选项与插件到其他配置」，快速将基线开关、市场配置与插件状态同步给其余 Profile。
- **外部变更与差异比对**：当检测到未托管的 `~/.claude/settings.json` 时会引导一键导入。若已绑定的文件被外部程序修改，卡片会提示 Diff 差异，支持选择「接受实际配置」反向更新托管数据，或选择「重新应用」强行覆写。

### 新建或编辑配置

右侧配置抽屉按职责拆分为结构化模块：

- **基础信息**：配置名称（必填）、描述说明、关联供应商（选择后自动注入服务地址与模型映射）。
- **认证凭据**：填写认证密钥（写入 `env.ANTHROPIC_AUTH_TOKEN`）与服务 Base URL（写入 `env.ANTHROPIC_BASE_URL`，留空时默认走 Anthropic 官方端点）。
- **模型与行为**：默认模型（提供可输入下拉框，预置当前供应商推荐模型，也支持手动输入任意模型）、思考程度（Effort，可选 `auto`/`low`/`medium`/`high`/`xhigh`/`max`）、Opus / Sonnet / Haiku 映射模型、Subagent 子代理模型、回复语言偏好与输出样式。
- **常用功能开关**：可视化开关深度思考（Deep Thinking）、Thinking 摘要展示、Fast Mode、禁用 Hooks、禁用 AI 署名、LSP 工具支持、Tool Search、新版 Init、无闪烁模式、子进程凭据脱敏以及 Agent Teams 等核心参数。
- **环境变量**：集中维护自定义 `env` 键值对。内置防重校验与 JSON 格式检查，编辑未保存时会阻断提交。
- **权限控制**：默认权限模式、禁用 `bypassPermissions` 开关、设置允许/拒绝/确认规则清单，支持添加目录信任与一键载入推荐规则预设。
- **Sandbox 沙箱**：沙箱启闭开关，支持载入推荐预设，复杂需求可无缝切换至高级 JSON 模式。
- **Hooks 钩子**：维护各阶段钩子脚本并展示摘要，内置常见乱码排查预设，支持切换 JSON 模式。
- **插件市场**：维护 `extraKnownMarketplaces`，预置官方插件市场（`claude-plugins-official`）与社区市场（`claude-community`）配置模板，支持从界面一键导入。
- **插件管理**：管理 `enabledPlugins`，包含「已配置」和「浏览市场」双标签页。支持按市场、启用状态、分类多维检索，开启后即时同步；网络请求与安装计数均设超时保护。
- **状态行（Statusline）**：配置自定义状态栏输出脚本，内置默认状态行预设（macOS/Linux 写入 `~/.claude/statusline.sh`，Windows 写入 `~/.claude/statusline.ps1` 并自动配置 PowerShell 执行指令），附带 60 秒定时刷新保证缓存倒计时准确。
- **最终配置预览**：实时预览供应商预置与配置选项合并后的完整 JSON；同时提供源码编辑模式直接修改完整 settings 对象。

### 模型测试

点击「测试模型」会基于当前编辑内容即时向模型端点发起验证请求：

- **全面诊断**：测试结果弹窗详细展示连通状态、实际调用与返回模型名称、服务端点、HTTP 状态码、请求耗时、Request ID、停止原因、输入/输出文本、完整 Header 标头、请求 Body 及原始响应报文。
- **实用操作**：支持一键复制等价 cURL 命令在终端重现，或现场修改 Prompt 快速复测。
- **网关兼容**：对于要求按会话声明标识头的网关（如 OpenCode Go），测试器会自动生成并注入合法标头，无需繁琐的手动配置。

### 深度链接导入

支持通过系统自定义 URL Scheme 将 Claude 配置直接拉起并导入 Code Manager，格式为 `code-manager://profiles/import`。

- **两种数据源（互斥）**：
  - **内嵌载荷**：`payload=`（base64url 编码的纯 settings JSON，限制解码后约 16KB 上限）。
  - **远端获取**：`url=`（仅限 HTTPS 地址，应用拉取后导入，内置 SSRF 防护与重定向限制）。
- **预填参数**：可选附带 `name` 与 `description` 预填导入弹窗。
- **安全不自动激活**：链接解析成功后进入配置预览对话框；用户确认后**创建新 Profile**（`providerId` 为空），**绝对不会**自动覆写或直接生效至 `~/.claude/settings.json`。
- **敏感密钥防护**：若导入载荷中包含鉴权凭据，必须由用户显式勾选安全风险确认后才允许导入。从已有配置复制 Deep Link 时默认排除密钥。
- **可靠排队机制**：连续调起多条链接时自动进入后台队列排队，页面切换不会丢失未确认的导入请求。

## 供应商 Provider

所有供应商均为**内置只读**设计，仅包含标准的服务端点信息（`ANTHROPIC_BASE_URL`、模型名映射及必要的基础环境变量），不包含任何私有 API 密钥。

- **生态覆盖**：涵盖 Anthropic、DeepSeek、智谱 GLM Coding Plan、Kimi Code Plan、MiniMax Token Plan、小米 MiMo Token Plan、OpenRouter、火山方舟 Coding Plan、万界方舟、OpenCode Go 以及 Ollama 本地部署。
- **使用方式**：在配置抽屉的「供应商」下拉框中直接选择，端点与推荐模型将自动填入；点击选项下方的「查看内置供应商」可打开只读速查抽屉，查看各厂商文档、端点及推荐模型。

## 记忆管理

记忆页面专用于集中维护 Claude Code 用户级系统指令。

- **Karpathy 行为指南预设**：当尚未配置主记忆时，页面顶部会呈现 Karpathy 行为指南推荐卡片，支持一键创建并启用为 `CLAUDE.md`。在编辑已有的 `CLAUDE.md` 时，亦支持将该指南一键追加至文末（内置防重复追加标记）。
- **新增记忆**：填写记忆名称，选择类型（`CLAUDE.md` 写入 `~/.claude/CLAUDE.md`，全局单例启用；Rules 写入 `~/.claude/rules/<path>.md`，可多选同时启用并支持 `paths` glob），编写 Markdown 正文后保存。只有在列表中点击「启用」，文件才会真正写入磁盘。
- **日常维护**：支持更新内容、克隆禁用副本、安全删除无用规则目录。
- **接管与导入**：
  - **本地识别**：自动探测 `~/.claude` 下未受管的 `CLAUDE.md` 与 `rules/*.md`，支持一键原地接管。
  - **批量目录导入**：选择外部包含指令文件的目录进行批量导入，默认以禁用状态存入；自动跳过重复项或无效软链接。

## Skills 管理

Skills 页面统一管理 `~/.claude/skills/` 下的 Claude Code 技能包。

- **新增技能**：录入 Skill 唯一标识符（目录名 / slash 命令名，仅允许小写字母、数字和中划线）、显示名称、功能描述，并编写 `SKILL.md` 正文。支持按需开启「仅手动触发」（写入 `disable-model-invocation`）或「允许手动调用」。
- **状态维护与归档**：
  - **启用**：存放在 `~/.claude/skills/<id>/`。
  - **禁用**：安全移至应用数据目录的 `skills-disabled/<id>/` 隔离保存，不污染 Claude 工作区。
  - 支持一键同步软链接至 `~/.codex/skills`。
- **导入技能**：支持导入单个 Skill 目录、Skill 软链接或包含多个技能的集合目录。软链接技能带有只读提示，可在应用内启停或打开源目录，但不允许直接修改内容。
- **辅助资源树**：编辑器支持查看 `SKILL.md` 之外的脚本与模板资源树；修改辅助文件支持一键唤起外部编辑器。

## 项目管理

项目页从 `~/.claude/history.jsonl` 中自动提取项目索引，按最近活跃时间倒序排列。进入项目详情时会结合本地实际工作区读取 Git 仓库、Worktree、项目级 Claude 配置与状态。

### 项目列表与详情

左侧列表展示项目缩写、磁盘路径、最近活跃时间、会话与交互总数及最近 Session ID。点击即可进入右侧详情视图。

### 快捷操作

- **终端打开**：根据「设置」中配置的默认终端唤起，智能结合当前操作系统与本地已安装程序。
- **编辑器打开**：调用「设置」中预设的默认代码编辑器打开工作区。
- **访问远端仓库**：解析 Git Remote URL 并在默认浏览器中打开对应代码托管页。

### 编辑器与终端支持矩阵

| 工具类型 | macOS | Linux | Windows |
| --- | --- | --- | --- |
| VS Code | 原生应用打开 | 需安装 `code` CLI | 需安装 `code` CLI |
| Zed | 原生应用打开 | 需安装 `zed` CLI | 需安装 `zed` CLI |
| 系统终端 | Terminal.app | 依次回退 `$TERMINAL`、`xdg-terminal-exec`、`x-terminal-emulator` | 依次回退 Windows Terminal、PowerShell、cmd |
| iTerm2 | 完整支持 | 不支持 | 不支持 |
| Ghostty | 完整支持 | 需安装 `ghostty` CLI | 暂不支持 |

### 状态检查

项目详情页提供全面的健康状态诊断：
- 目录与 Git 仓库状态、当前分支与最近提交记录、Worktree 路径与检出状态。
- `CLAUDE.md ↔ AGENTS.md` 互联状态、`.claude/skills ↔ .agents/skills` 技能目录配对状态。
- 最近会话列表（支持点击直接下钻查看交互回放）。
- 快速跳转：一键直达该项目的历史记录页或该项目的 Token 用量页。

### 项目级 Claude 配置

针对多 Agent 协同与项目级配置提供三大能力：
- **记忆配对**：`CLAUDE.md ↔ AGENTS.md` 双向相对软链接配对，保证不同 AI 工具均能读取规范约定。
- **技能配对**：`.claude/skills ↔ .agents/skills` 技能目录软链接互联。
- **项目级 `.claude/` 管理**：在右侧抽屉中浏览与预览项目级 Claude 文件，支持一键新建 `settings.json` 与 `settings.local.json`。

### 分支与 Worktree 清理

自动扫描本地已合并或远端已删除的无用分支与孤立 Worktree。
- **安全两阶段操作**：先生成可供勾选的待删除预览清单，用户确认后才会执行物理删除，后端绝不清理未在清单中的条目。

### 清除项目本地数据

在项目列表右键选择「清除本地数据」，应用会先展示由 Claude CLI 评估的 Dry-run 删除规划，经过用户确认后才执行，安全清理 Claude CLI 遗留的本地会话状态缓存。

## 使用历史

历史页直接解析 `~/.claude/history.jsonl`，用于快速复盘历史输入提示与完整交互会话。

- **检索与过滤**：左侧按项目聚合归类；顶部展示近期交互密度的热力图；搜索框支持按文本全文检索；URL 同步维护 `project`、`q` 与 `session` 参数，方便随时收藏与分享过滤状态。
- **会话交互回放**：会话详情抽屉完整还原交互时序，清晰标注用户 Prompt、助手响应、Thinking 深度思考摘要、工具调用与执行返回、Shell 命令、附带图片、Plan 规划步骤及系统通知事件。
- **实用操作**：支持复制路径、Session ID、单条消息正文，或直接在外部编辑器中打开原始 `.jsonl` 文件。

## 使用统计

统计页直接读取 `~/.claude.json` 中的本地统计快照（非实时运行时计算结果）。

- **概览数据**：呈现累计启动次数、首次使用日期、管理项目总数、上次 Plan Mode 运行时间与 `btw` 调用次数。
- **图表与排行**：内置工具调用频次柱状图、Skill 使用热度排行。
- **最近活跃记录**：列出每个项目最近一次会话的详细指标，包括费用估算、会话时长、增删代码行数、各项 Token 构成、Web 搜索次数、调用模型及首条 Prompt。

## Token 用量统计

用量页深入扫描 `~/.claude/projects/**/*.jsonl` 与 `subagents/*.jsonl`，提取助手响应中的 `usage` 载荷，结合权威价格表核算 Token 与实际费用支出。

### 数据口径

- **去重逻辑**：按 `message.id` 全局去重；若同一消息在日志中多次出现，优先保留 Token 用量更高的记录。
- **Token 构成**：涵盖输入（Input）、输出（Output）、缓存写入（Cache Creation）与缓存读取（Cache Read）；费用按 USD / 1M tokens 标准统一折算。
- **价格加载顺序**：本地缓存 `model-pricing.json` → 内置 Anthropic 官方兜底表 → 启动或手动刷新时从 models.dev 拉取最新行情。
- **官方厂商收录**：models.dev 仅收录官方 Provider 定价（Anthropic、Moonshot/Kimi、智谱 GLM、MiniMax、小米 MiMo、DeepSeek）。其中国产模型受「设置」中的「第三方模型计价」开关控制，关闭后费用按 0 计入。
- **未识别模型**：无法匹配价格的模型 Token 正常累计，但费用计为 0 并归入未识别模型列表。

### 顶部状态与操作

顶部常驻当前价格表来源指示（内置 / 本地缓存 / models.dev 实时），提供一键刷新行情、查看模型单价表（可检索各模型输入、输出及缓存读写单价）与强制重新扫描按钮。

### 筛选

支持按自定义日期范围、常用快捷周期（今日、最近 7 天、最近 30 天、本周、本月、今年、全部历史）、关联项目以及模型名称（支持 `claude-*` 通配聚合）组合过滤。

### 图表与表格

- **统计看板**：呈现总支出、总 Token、会话数、交互消息数与 Prompt 缓存节省成本。
- **多维趋势**：支出趋势图与 Token 趋势图支持按模型或 Token 类型拆分，支持曲线/柱状图切换，提供日 / 小时 / 5 分钟三级粒度，图例支持单选与隔离查看。
- **明细下钻**：提供按日期、项目、会话、模型汇总的数据明细表；在会话明细中点击特定 Session 可展开单条消息级别的 Token 消耗瀑布流。

## 桌面用量浮窗

桌面用量浮窗是一个常驻置顶、半透明、无系统边框的轻量桌面小窗，方便在专注编码时不打开主程序即可实时掌控消耗。

- **实时同步**：与用量分析引擎共享同一数据源，日志变动或价格更新时静默刷新。
- **一键跳转**：点击浮窗主体即刻唤起 Code Manager 并直达用量统计页面。
- **外观定制**：可在设置中自由调节浮窗整体透明度（30%–100%）。

## 本地数据与隐私

Code Manager 严格践行**本地优先（Local-First）**与隐私保护原则。配置合并、本地扫描、用量计算与日志审计均 100% 在本机离线执行，除由用户主动触发的模型连通性测试与公开定价获取外，绝不上报任何私有代码或配置信息。

### 应用管理数据

| 平台 | 路径 |
| --- | --- |
| macOS | `~/.config/code-manager/` |
| Linux | `$XDG_CONFIG_HOME/code-manager/` 或 `~/.config/code-manager/` |
| Windows | `%APPDATA%\code-manager\` |

> [!NOTE]
> 在 macOS 上，本应用特意使用 `~/.config/code-manager/` 替代传统的 `~/Library/Application Support/...`，方便跨平台脚本管理与统一配置同步。

```text
<应用数据目录>/
  config-registry.json    # 托管的配置注册表
  memories.json           # 托管的指令与规则库
  model-pricing.json      # 本地模型价目表缓存
  skills-disabled/        # 禁用的技能归档目录
```

```text
~/.claude/
  settings.json           # 最终生效的用户配置
  CLAUDE.md               # 激活的主记忆

```

## 常见工作流

### 创建并启用一个供应商配置

1. **新建配置**：进入「配置」页新建配置，在「供应商」中选定对应的内置服务商，填入对应的 API 密钥。
2. **调优参数**：在模型和常用选项中微调参数，在「最终配置预览」中核对生成的 `env` 与权限规则。
3. **连通性测试**：点击「测试模型」，测试通过后点击保存。
4. **生效验证**：在配置列表中点击「启用」，随后切换至「`~/.claude` 目录总览」确认 `settings.json` 已正确写入。

### 接管已有 `CLAUDE.md` 和 Rules

1. **识别接管**：进入「记忆」页，在「未导入」区域找到本地现存的规则文件，点击「导入管理」就地接管。
2. **审核状态**：检查正文内容与目标路径映射，在列表中根据项目需求开启或禁用。

### 创建 Skill 并同步给 Codex

1. **编写技能**：进入「Skills」页点击添加技能，填入合法标识符、名称与描述。
2. **正文编写**：编写 `SKILL.md` 正文，设定调用触发机制并勾选启用。
3. **建立软链**：在卡片菜单中点击「同步到 `~/.codex/skills`」，完成双环境联动。

### 排查模型无法调用

1. **排查凭据**：编辑当前激活的配置，仔细核对 API 密钥、端点 Base URL 与模型名称是否匹配。
2. **现场复测**：点击「测试模型」，重点查看返回的 HTTP 状态码、报错信息与原始响应报文。
3. **定位原因**：若需要脱离应用排查，可直接复制 cURL 命令在终端独立复现；若是应用自身报错，可在「设置 → 诊断 → 查看日志」中检索系统错误日志。

### 排查费用或 Token 异常

1. **圈定范围**：进入「Token 用量」页，将时间范围、目标项目与模型进行筛选，查看费用占比与明细构成。
2. **核对单价**：打开模型价目表，确认该模型是否已获取到正确单价；在会话明细表中定位到异常 Session，展开单条消息瀑布流分析消耗根因。
3. **排查归零**：若模型出现在未识别列表，尝试点击刷新价格；若为国产模型，确认「设置」中的第三方计价开关是否开启。

## 常见问题

### 启用配置后写到哪里？

**写入 `~/.claude/settings.json`。**
写入内容是所选供应商的预置环境变量与用户在配置中定制的选项合并后的完整 JSON，并自动带入官方 Schema 定义以保证编辑校验。

### 删除配置会删除 `settings.json` 吗？

**不会。**
删除配置操作仅从 Code Manager 的内部注册表中移除该条管理记录，绝不会擅自删除或清空磁盘上已经生效的 `~/.claude/settings.json`。

### 为什么模型测试提示缺少 `ANTHROPIC_AUTH_TOKEN`？

**当前配置未解析出可用的鉴权凭据。**
请检查是否在「认证」区域填入了 API 密钥，或者在高级 JSON 模式中确认 `env.ANTHROPIC_AUTH_TOKEN` 是否被意外覆盖为空值。

### 为什么项目页没有项目？

**本地尚未生成 Claude Code 历史记录。**
项目页的数据源是 `~/.claude/history.jsonl`。当你在终端中使用 Claude Code 开展过任何会话后，项目就会自动索引并呈现在列表中。

### 为什么统计页和用量页费用不一致？

**两者的数据源与计算逻辑不同。**
「使用统计」页呈现的是 `~/.claude.json` 中的静态统计快照；而「Token 用量」页则是遍历扫描所有项目的 `.jsonl` 原始日志，并按当前最新价目表重新精确复核的结果。

### 为什么某些模型费用为 0？

**模型未命中价格表或第三方计价开关已关闭。**
当调用模型未收录在 models.dev 价目表中时，其 Token 会被正常统计但单价按 0 处理；此外，若国产模型计价开关处于关闭状态，Kimi、GLM、DeepSeek 等模型也会计为 0。请尝试刷新价格或前往设置开启开关。

### 如何更新 Claude Code 插件？

**在 Claude Code 终端中执行更新命令。**
Code Manager 仅负责管理配置文件中的 `enabledPlugins` 与 `extraKnownMarketplaces`，本身不执行插件文件的拉取或构建。请在终端执行 `claude plugin update <插件名>@<marketplace>` 或在会话中使用 `/plugin marketplace update <marketplace>` 进行更新；亦可在配置中将对应市场的 `autoUpdate` 属性设为 `true`。详见官方文档 [Discover and install plugins](https://code.claude.com/docs/en/discover-plugins)。

### 为什么不能编辑软链接 Skill？

**软链接指向的源文件位于外部目录。**
为了防止越权篡改外部代码库，Code Manager 对软链接技能仅提供启停开关与目录定位能力，正文编辑请在源目录中进行。

### 清除项目本地数据安全吗？

**具有二次确认与 Dry-run 机制，但仍需谨慎。**
该操作调用 Claude CLI 清除该项目保存的本地会话历史与上下文缓存。应用会首先展示待删除文件规划清单，确认无误后再执行，避免误伤其他数据。

### 为什么看不到 LED 灯效联动或会话聚焦快捷键？

**这两项功能专属于 macOS 平台。**
在 Linux 与 Windows 系统的设置中会自动隐藏这些选项。此外，LED 灯效还需物理连接兼容的 ANTICATER USB 外设硬件，并在设置卡片中开启开关且配置相应的有效光效模式。
